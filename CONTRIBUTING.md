# Contributing

Contributions are welcome. Keep changes focused and explain the user problem they solve.

## Development

1. Fork and clone the repository.
2. Use PHP 8.2 or newer.
3. Run `php tests/run.php` before opening a pull request.
4. Add or update tests for behavior changes.
5. Do not commit secrets, production databases or files from `storage/`.

## Pull requests

A good pull request contains a concise description, reproduction steps when fixing a bug, tests, and notes about backward compatibility. Large architectural changes should begin as an issue so the design can be discussed first.

## Code style

Use strict types, explicit parameter/return types where practical, small classes, prepared SQL statements and framework-independent PHP.
